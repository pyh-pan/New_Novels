# 通用 UX 迭代设计

日期：2026-04-29

状态：用户评审草案

## 目标

本次迭代在不改变核心 agent 架构的前提下，优化当前可玩的推理小说原型。目标是让原型更像一个可用的“阅读 + 调查”产品：

- 保留桌面端双栏体验；
- 让侦探笔记适合重复调查；
- 在本地持久化玩家进度；
- 引入需要明确确认的重置 / 重新开始流程；
- 将故事栏升级为基于 Pretext 的章节阅读器；
- 改善对话人体工程学；
- 增加基于三个聚焦标签的移动端体验。

迭代有意拆成小版本，使每个变化都能被清楚评审、测试和提交。

## 已确认产品决策

### 阅读模型

故事区使用基于章节的阅读模型。

- 一章显示为一个连续可滚动阅读页。
- 本阶段不使用页码式分页。
- 每章底部包含前一章和后一章按钮。
- 阅读章节时，点击故事区域会显示轻量浮动章节导航。
- 浮动导航会在短暂延迟后自动淡出。
- 第一章禁用前一章导航。
- 最后一章禁用后一章导航，或后续可以暴露最终指认等下一步产品动作。

### Pretext 使用方式

Pretext 在 V2 引入，但它支持章节滚动模型，而不是用分页取代它。

Pretext 作为故事阅读器的文本布局基础：

- 为稳定布局准备章节文本；
- 测量和切分长文本；
- 支持未来的排版、行距和阅读进度增强；
- 降低后续重写故事阅读器的概率。

第一版 Pretext 集成应保持保守：

- 渲染普通可读 DOM 文本；
- 在可行处使用 Pretext 做布局准备或测量；
- 如果 Pretext 失败或无法测量，回退到普通段落渲染；
- 本版本避免虚拟化故事页。

### 笔记交互

侦探笔记通过主页面右上角小按钮打开。关闭时不占用完整侧边栏轨道。

笔记行为：

- 笔记可按标签筛选；
- 标签包括 clue、testimony、doubt 和 contradiction；
- 笔记可手动新增和编辑；
- 删除笔记必须确认；
- 默认按最新优先排序；
- 系统不应判断哪些笔记“重要”；
- 未来的“重要”或“置顶”状态也应由用户控制；
- 最终指认入口停留在笔记底部。

### 重置交互

应用应在右上角工具区附近提供重置 / 重新开始入口，靠近笔记按钮。

重置行为：

- 重置始终打开自定义确认弹窗；
- 应尽量避免误触；
- 确认后清空本地游玩状态；
- 取消后保留全部内容。

### 持久化范围

本地持久化应覆盖第一版完整游玩状态：

- 当前章节；
- 对话历史；
- 展开或激活的对话模块；
- 侦探笔记；
- 有价值时保存当前笔记筛选 / 搜索 / 排序；
- 玩家已知状态；
- 调查台相关 UI 状态。

本次迭代仅使用 localStorage，不包含账号系统或服务端存档 / 继续游玩。

### 移动端模型

桌面端和移动端应使用不同布局。

桌面端保持：

- 左侧：故事阅读器；
- 右侧：调查台；
- 右上角：笔记抽屉按钮。

移动端变成三标签应用：

- 故事；
- 调查；
- 笔记。

所有标签共享同一份底层游玩状态。

## 版本计划

### V0：Git 基线

实现前初始化 git，确保未来所有迭代都可审查和安全回退。

任务：

- 如果仓库尚未初始化，运行 `git init`；
- 检查工作区；
- 为当前原型创建初始基线提交；
- 不包含本地专属产物或密钥。

验收标准：

- 基线提交后 `git status` 干净；
- 当前原型文件被完整保留，除非有意忽略。

### V1：笔记、持久化和重置

在不触碰故事阅读器架构的情况下改善调查循环。

笔记任务：

- 增加手动新建笔记；
- 保留标题、正文和标签编辑；
- 增加带确认的笔记删除；
- 默认按最新优先排序；
- 可选地在笔记数据中保存创建 / 更新时间；
- 保留标签筛选；
- 为无笔记和无匹配筛选结果提供清晰空状态。

持久化任务：

- 引入类型化 localStorage 保存结构；
- 持久化对话、笔记、玩家状态、当前章节和关键 UI 状态；
- 加载时安全 hydrate；
- 容忍缺失字段或旧版本字段；
- 避免无效 JSON 导致崩溃。

重置任务：

- 在右上角区域附近增加小型 reset / restart 工具按钮；
- 清空任何内容前展示自定义确认弹窗；
- 仅在确认后清空 localStorage；
- 将玩家返回初始章节和初始调查状态。

验收标准：

- 浏览器刷新后保留调查状态；
- 删除笔记必须确认；
- 重置必须确认；
- 重置后回到干净初始状态。

### V2：Pretext 章节阅读器与对话打磨

升级阅读界面，让调查台更流畅。

故事阅读器任务：

- 将故事数据从单一文本块改为有序章节结构；
- 创建或重命名故事组件为面向章节的 `StoryReader`；
- 将 `@chenglou/pretext` 集成为故事布局基础；
- 将一章渲染为连续可滚动阅读页；
- 增加底部前一章 / 后一章控件；
- 在故事区域内增加点击显示的浮动章节导航；
- 短延迟后自动隐藏浮动导航；
- 通过 localStorage 持久化当前章节；
- 如果 Pretext 布局失败，提供普通 DOM 回退。

对话打磨任务：

- 保持一个全局输入模型；
- 保持路由行为：通用问题留在 general 模块，NPC 问题路由到匹配 NPC 模块；
- 改善 loading 状态，使激活模块清楚显示正在生成回答；
- 改善消息层级与间距；
- 增加键盘友好的提交行为；
- 保持摘录保存反馈轻量且可见；
- agent 调用失败时显示清晰错误气泡。

笔记打磨任务：

- 故事和对话 UI 变化时仍保持笔记可用；
- 确保保存摘录仍能正确创建笔记；
- 保留最新优先排序；
- 保留标签筛选。

非目标：

- 不做多幕动态故事状态；
- 不做页码式分页；
- 不做对话虚拟化；
- 不做服务端持久化；
- 不做富文本创作系统。

验收标准：

- 完整章节可作为滚动页自然阅读；
- 章节底部按钮可用；
- 点击故事区域显示临时章节导航；
- Pretext 出现在故事阅读路径中，并有回退；
- 调查对话仍能路由并保存摘录。

### V3：移动端底部标签

创建移动端专属布局，而不是把桌面端双栏界面挤进小屏幕。

移动端布局：

- 底部固定标签：故事、调查、笔记；
- 每个标签填满可用视口；
- 切换时保留标签状态；
- 共享游玩状态会立即同步到所有标签。

故事标签：

- 展示与桌面端相同的章节阅读器；
- 支持连续章节滚动；
- 支持点击显示章节导航；
- 保留底部章节导航。

调查标签：

- 默认展示通用调查助手；
- 以移动端友好的可折叠列表展示对话模块；
- 输入框靠近屏幕底部；
- 需要时自动展开被路由的 NPC 模块；
- 摘录保存时给出轻量反馈。

笔记标签：

- 展示筛选器、搜索（如果实现）和最新优先笔记；
- 支持新建、编辑、带确认删除；
- 最终指认按钮停留在底部；
- 最终指认在视觉上与普通笔记操作区分开。

桌面行为：

- 保持双栏布局；
- 笔记仍作为从右上角工具按钮打开的抽屉；
- 不为了支持移动端而改变桌面结构。

验收标准：

- 移动端视口一次只展示一个主要工作区；
- 标签切换不丢失对话、故事或笔记状态；
- 笔记操作在移动端可用；
- 最终指认可发现。

## 数据结构变化

### 章节（Chapter）

```ts
type StoryChapter = {
  id: string;
  title: string;
  subtitle?: string;
  body: string[];
  previousChapterId?: string;
  nextChapterId?: string;
};
```

`body` 是段落数组，因此 reader 不需要在渲染时按换行拆分。

### 本地保存（Local Save）

```ts
type LocalPlayState = {
  version: number;
  currentChapterId: string;
  conversations: ConversationModule[];
  notes: NotebookNote[];
  playerState: PlayerKnowledgeState;
  ui: {
    activeNotebookFilter: NoteFilter;
    activeConversationId?: string;
    notebookOpen?: boolean;
    mobileTab?: "story" | "investigation" | "notebook";
  };
  savedAt: string;
};
```

第一版实现应包含 version number，便于未来迁移旧存档。

### 侦探笔记（Notebook Note）

```ts
type NotebookNote = {
  id: string;
  title: string;
  text: string;
  tag: NoteTag;
  source?: string;
  createdAt: string;
  updatedAt: string;
};
```

除非用户后续明确要求，否则本次迭代刻意不包含 important 或 pinned 状态。

## 风险与缓解

### Pretext API 适配

风险：Pretext 可能无法完美映射到当前 React 故事组件。

缓解：

- 保持 DOM 渲染路径简单；
- 先把 Pretext 用作布局 / 测量层；
- 将 Pretext 集成隔离在小 helper 中；
- 提供回退渲染。

### 保存结构漂移

风险：修改笔记或对话数据可能破坏旧 localStorage 状态。

缓解：

- 为保存状态加版本；
- hydrate 前验证并规范化保存数据；
- 如果保存数据无效，回退到初始状态。

### 移动端范围膨胀

风险：移动端布局可能变成第二套完整产品。

缓解：

- 第一版移动端只做导航和布局；
- 复用现有 story、investigation 和 notebook 组件；
- 避免移动端专属业务逻辑。

### 误触重置

风险：重置可能清空用户调查进度。

缓解：

- 使用自定义确认弹窗；
- 破坏性文案必须明确；
- 取消应是容易选择的默认路径。

## 验证计划

- 故事章节导航；
- 点击故事区显示浮动导航；
- 调查路由和保存摘录；
- 移动端故事标签；
